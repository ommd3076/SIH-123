2. CORE SYSTEM MODEL
==================================================

Implement three primary runtime actor types.

A. ROBOT EDGE AGENT

Each simulated AMR owns:

- robot ID
- pose
- velocity
- health
- current task
- battery state
- current route
- next junctions
- trajectory intent
- local context cache
- reservation state

Each robot should independently run logic equivalent to:

→ route generation
→ local intent
→ conflict awareness
→ reservation logic
→ deterministic safety check
→ movement execution.

The robot must remain capable of basic operation if Junction Edge Cells fail.

B. JUNCTION EDGE CELL — JEC

Create logical JEC processes at strategically important junctions.

A JEC knows ONLY its local area.

It maintains:

- connected aisles
- capacities
- current occupancy
- predicted occupancy
- approaching robots
- local queue
- reservations
- blockage state
- traffic direction
- congestion estimate
- relevant contextual memory

A JEC does NOT:

- issue motor commands
- own the global map
- compute global routes
- become mandatory for robot safety.

JEC = local coordination accelerator.

4. CONFLICT CELLS
==================================================

Do NOT make every robot coordinate continuously with all nine others.

Construct a conflict graph.

Robots become connected when their predicted spatiotemporal occupancy overlaps or they compete for the same scarce resource.

When:

R2
R5
R8

all intend to use J7 within conflicting intervals, form:

ConflictCell-J7-{R2,R5,R8}

Only those robots and the relevant JEC participate in high-frequency negotiation.

After the conflict clears:

destroy / expire the conflict cell.

Demonstrate that communication complexity follows local conflicts rather than total fleet size.

==================================================
8. PROSOCIAL ROUTING
==================================================

Do not optimize every robot independently for shortest distance.

Create a social-cost function.

Initial model:

route_cost =
w_distance * own_travel_time
+
w_wait * expected_wait
+
w_energy * estimated_energy
+
w_congestion * congestion_cost
+
w_externality * estimated_delay_imposed_on_local_fleet
+
w_risk * safety/risk_cost.

The important term is:

EXTERNALITY.

Example:

R1 saves 3 seconds by entering A4,
but causes three other robots a combined 16-second delay.

The planner should be capable of selecting the slightly longer route.

Limit externality calculation to the robot's local prediction horizon / conflict neighborhood so computation remains tractable.

Make weights configurable from the dashboard/config file.

Create a metric that detects starvation.

A low-priority robot must eventually make progress.

10. EDGE AI
==================================================

AI MUST NOT directly command wheel velocities.

AI belongs only in prediction / optimization support.

Implement at least ONE actually working lightweight predictive component.

Preferred first component:

LOCAL CONGESTION PREDICTOR.

Inputs may include:

- current occupancy
- approaching robot count
- queue length
- trajectory-intent count
- downstream occupancy
- task demand
- hour/simulated schedule
- recent blockage events.

Outputs:

- predicted occupancy
or
- congestion probability
for short future horizons.

Start with:
- heuristic baseline

Then implement one lightweight learned model.

Evaluate:
- XGBoost / LightGBM if convenient
- small MLP
- compact PyTorch model
- small GNN only if graph structure genuinely improves results.

DO NOT use a GNN just to claim "graph AI."

Generate simulation training data if real data is unavailable.

Store the generated dataset and training/evaluation pipeline.

Compare learned predictor against a simple baseline.

If ML fails to outperform the heuristic:
keep the deterministic heuristic as default and retain ML as an experimental option.

Accuracy must not be fabricated.
